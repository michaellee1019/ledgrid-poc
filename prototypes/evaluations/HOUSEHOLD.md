# Household evening usability evaluation

## Persona and method

I evaluated these as a household partner or guest, not as the wall's builder: low technical literacy, mildly rushed, often holding a phone in one hand, and mainly wanting the room to feel right. My practical questions were: *What is on the real wall? Can I stop it? Can I look without changing it? What will this button do to the room?*

I opened and exercised every candidate at desktop width and then at approximately 390 px. I did that before reading any candidate `README.md`, `PARADIGM.md`, or product-decision document, so terminology and first-click confusion below are cold-start evidence. I used the visible interface rather than source inspection to judge task success. Only after all browser passes did I read the documents for the backend-fit score. The interfaces were deterministic prototypes, so “clicks” below means primary button/link/control activations; it excludes scrolling, typing in a search field, and opening/closing the browser itself.

The five candidates were:

- Wall Conductor (`wall-conductor`)
- Wall Studio (`finder-wall-studio`)
- Room Tune (`cold-ambient-paradigm`)
- Lumen Loom (`cold-spatial-paradigm`)
- Lumen Path (`cold-journey-paradigm`)

I tested ordinary pointer/touch-like clicks and basic keyboard activation. This was not a full screen-reader audit. A prototype fixture acknowledging an action counts as interaction-model evidence, but decorative polish does not.

## Verdict at a glance

Room Tune is the best household remote. It gets a non-expert to “settle the room,” keeps rehearsal separate from live output, and remains genuinely usable on a narrow phone. Wall Conductor has the most complete truth and backend-shaped control model, but its common phone handoff did nothing and its brightness path misrouted. Lumen Path has an excellent guided evening journey, catalog, and phone composition, but a contradictory duration and an inaccessible press-and-hold block the decisive live action. Wall Studio is very safe and information-rich on desktop, yet broken search, surprising preloaded comparison, and stacked inactive workspaces on phone make it feel like an operator utility. Lumen Loom is an evocative installation workbench, not a viable household controller; its phone layout is effectively unusable.

The decisive deductions are functional, not stylistic:

- Wall Conductor's phone **Take this preset live** action was an observable no-op for multiple ready presets.
- Lumen Path and Lumen Loom required a pointer press-and-hold for the final live transition; ordinary click and keyboard activation did not complete it.
- Wall Studio's search did not filter, its developer inventory control was inert, and its supposedly phone-specific workspaces stacked below the active one.
- Lumen Loom collapsed into a tiny desktop-like strip at phone width and omitted the stop/start control from the usable header.
- In four candidates, brightness was absent or did not respond to basic keyboard operation. This is a core evening control, not a minor settings omission.

### Why it ranks last

The documentation understands provider qualification, transactional staging, exact wall geometry, fallback, scene receipts, and expected-degraded telemetry, so backend fit is not the main problem. ## Cross-candidate kit of parts

The strongest product is not one prototype unchanged. It is a household shell led by Room Tune, with these proven parts:

1. **A persistent physical-wall ribbon from Wall Conductor / Wall Studio.** Always show provider-qualified component + preset, background/overlay role, power/output, saved/dirty/drift, brightness, actual/target FPS, Vibe, and an immediate **Stop output**. Stop should state whether power remains on and return a visible receipt.
2. **Intent-first entrances from Room Tune and Lumen Path.** Lead with **Settle**, **Welcome**, **Focus**, and **Play**, but always provide **Browse all 52 components / ~292 presets**. An intent is a reversible filter, not a content silo.
3. **A scalable browser from Wall Studio, softened with Room Tune's language.** Use category → component → preset hierarchy, working search, source/provider/role/readiness facets, complete wrapping names, counts, and a zero-result action that removes the blocking filter.
4. **One preview-truth plaque everywhere.** Copy the clarity of Wall Conductor and Room Tune: **Isolated preview; never changes the physical wall. Receiver-native view is a host simulation, not framebuffer readback.** Repeat it in detail and comparison rather than relying on a global legend.
5. **A deliberate comparison tray.** Borrow Wall Conductor's explicit side-by-side review and Lumen Loom's exact 32:138 specimens. Start empty, allow two or three pinned alternatives, never evict silently, synchronize motion when helpful, and repeat full name/provider/role/availability under every specimen.
6. **A conventional, accessible take-live review.** Combine Wall Studio's attached before/after sheet with Lumen Loom's preflight receipt: current live state → proposed state, validation/fallback, globals that will *not* change, intended wall, and one normal keyboard/touch-operable final button. Do not make press-and-hold the only activation path. Return success, pending, or actionable failure—not silence.
7. **Room Tune's two-sheet scene model plus Wall Conductor's evidence.** Show exactly one Background and optional Clock Overlay, fallback, placement, opacity, clipping, stale policy, validation, source drift, isolated whole-scene preview, **Save layout only**, and a separate **Perform scene**. The save receipt must explicitly exclude Vibe, plant material, brightness, FPS, speed, and power.
8. **One independent Room Feel drawer.** Use the plain household verbs from Room Tune, the exclusivity constraints from Wall Studio, and the support/fallback evidence from Wall Conductor. Put Vibe, plant semantics, brightness, target FPS, and operator speed in one reachable place while visually separating authored animation speed and Vibe tempo. Show values changing, then provide Apply and a receipt.
9. **Visible unavailable content with a next step.** Keep build-only, unsupported, quarantined, and developer-only entries in search and browsing. Disable impossible live actions at first presentation, state why, allow safe rehearsal where possible, and offer a compatible substitute or route to resolution.
10. **Household-first health language.** Lead with Room Tune/Lumen Path's conclusion—whether all wall sections are receiving usable playback—then show expected-degraded return paths as policy, not generic failure. Offer a visual check when acknowledgement is impossible, with transport details behind disclosure.
11. **A true phone information architecture, not narrower desktop CSS.** Copy Room Tune's single-column river, bottom navigation, and full names. Keep the live/stop ribbon persistent and thumb-reachable; render only the active workspace. Test stop, browse, compare, confirm live, global adjustment, and recovery at 390 px as release-gating tasks.
12. **Semantic and failure-visible controls.** Every button and slider must work with keyboard as well as pointer/touch, show focus, expose a clear name, and acknowledge activation immediately. Search must alter result counts, sliders must show changed values, and an enabled consequential action must never be a silent no-op.

That kit keeps the warm, low-effort household experience without surrendering the provider, preview, scene, telemetry, and physical-change truth the real wall requires.
